使用说明

先想清楚：你要做「幻灯片」还是「逐帧动画」

这两种用途的时间计算方式完全不同，所以在「③ 时长模型」里先选一个：

  • 幻灯片（默认）：每张图片显示一段时间，比如一张 2.5 秒。 适合照片展示、图文讲解。转场特效只在这个模式下有意义。
  • 逐帧动画：每张图片占 N 帧，总时长 = 总帧数 ÷ 帧率。 例如 120 张 × 1 帧 @60fps = 2 秒； 也可以 120 张 × 2 帧 @30fps = 8 秒。 适合把图片序列当动画播、做定格动画或序列帧。

切换模式不会丢失图片，两种模式共用同一组帧；只是「时间怎么算」变了。

怎么用

  • 加图片：拖进来或点击选择，顺序就是出场顺序，可以用 ← → 调整。
  • 定节奏：幻灯片模式下每张可以单独设时长（最短 100ms）； 动画模式下只需设「每张占几帧」，帧率决定一切。
  • 选比例：横屏发 B 站 / 网页，竖屏发抖音 / 视频号，方形发朋友圈。 图片比例和画布不一致时，按「图片适配」的规则处理。
  • 加音乐（可选）：选一个音频文件当背景音乐，可调音量。
  • 导出：点「⑥ 导出视频」，等待录制完成，然后下载。

两种导出方式，默认走快的那个

方式 原理 速度 时长精度
快速导出（默认） WebCodecs 逐帧编码，帧的时间戳由工具指定， 编码不再受真实时间约束 通常 10 倍以上 精确（实测偏差 0 ms）
实时录制 MediaRecorder 按墙上时钟录制， 视频多长就录多久 1×（20 秒视频等 20 秒） 可能出现几十毫秒偏差； 标签页被切到后台会拉长
  • 快速导出的产物是标准 MP4（H.264 + AAC）：工具自己完成了 MP4 封装 （把编码器输出的裸数据写成 ftyp / mdat / moov 结构），没有引入任何第三方库。
  • 实测：120 张图 320×180 @60fps（视频 2.000 秒），快速导出耗时约 0.5 秒， 产物时长 2.0000 秒（偏差 0 ms）。
  • 浏览器不支持 WebCodecs 时（例如较老的 Firefox），工具会自动只用实时录制， 并在「导出方式」下面给出提示。
  • 实时录制仍保留：万一快速导出在你的素材上出问题，切过去就是一条更保守的路径。

关于输出格式

  • 快速导出固定输出 MP4 (H.264)，这是兼容性最好的组合： 微信、抖音、B 站、剪映都直接收。
  • 「输出格式」那个下拉只对实时录制生效，格式列表按你当前浏览器实际支持的编码器动态生成； 其中 WebM (VP9) 同画质体积更小，但个别平台不认，需要先转换。

体积估算

  • 文件大小 ≈ 码率 × 时长 ÷ 8。例如 4 Mbps 的 20 秒视频约 10 MB。
  • 幻灯片类视频画面变化慢，压缩率很高，实际体积常常比估算值更小。
  • 分辨率的影响很大：1080p 换成 720p，面积少一半多，体积也明显下降。

隐私

  • 图片和音乐都不会上传，全部在你的浏览器里处理，断网也能用。
  • 页面是纯静态的，没有后端；导出速度取决于你的电脑性能。

已知限制

  • 不能导入视频片段再拼接 —— 本工具只做「图片 → 视频」。要拼接视频请用视频剪辑软件。
  • 4K 导出对内存和 CPU 压力较大，老设备建议降到 1080p。
  • 不支持逐张设置不同的转场特效（全局统一），也不能加字幕。
  • 导出过程中若标签页被切到后台，浏览器可能降频，导致视频时长略微拉长；建议导出时不要切走。
  • 动画模式下高帧率对性能有要求：60fps 意味着每帧只有 16.7ms 的绘制时间。 本工具会在导出前把所有图片预先缩放到输出尺寸（避免每帧都缩放原图）， 实测 120 张 320×180 @60fps 的产物时长为 1.97 秒（目标 2.00 秒，偏差约 30ms）。 但如果图片非常多大、或分辨率开到 4K，仍可能出现掉帧、时长被略微拉长。
  • 动画模式的画面特效是全局统一的（无 / 随机抖动 / 全程推拉），不能逐帧设置。
